## How it works
Upstream's main new runtime flow is the cross-machine collector. When `remotes` is set in `config.json` (or `AOS_REMOTES`), `monitor.mjs` builds a collector with `createCollector`. Every 5 s, backing off up to 60 s on failure, the collector runs `ssh -o BatchMode=yes … -- <target> curl http://127.0.0.1:<port>/api/state?local=1` through `execFile`. It validates the reply with `parseState` and namespaces it with `tagRemote`. `mergeState` then folds all snapshots into the local `/api/state`.

```mermaid
sequenceDiagram
    participant UI as "Dashboard / aos-dash / MCP"
    participant Mon as "monitor.mjs (local)"
    participant Col as "remotes.mjs createCollector"
    participant SSH as "ssh (execFile)"
    participant Rem as "remote monitor 127.0.0.1:4318"
    loop every 5s, backoff up to 60s
        Col->>SSH: "ssh -o BatchMode=yes -- user@host curl …/api/state?local=1"
        SSH->>Rem: "GET /api/state?local=1"
        Rem-->>SSH: "JSON state (own machine only)"
        SSH-->>Col: "stdout, capped 8 MB"
        Col->>Col: "parseState + tagRemote (ids → name:id)"
    end
    UI->>Mon: "GET /api/state"
    Mon->>Col: latest snapshots
    Mon->>Mon: "mergeState(local, snaps)"
    Mon-->>UI: "agents/tasks with machine, machines, totals, cost.by_machine"
```
